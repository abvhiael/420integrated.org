Getting started / Security

verify before you sign.

Most blockchain security failures happen at the user interface layer: fake websites, malicious approvals, leaked recovery material and transactions signed without verification.

protect recovery secrets

No legitimate 420 Integrated application, developer, moderator or support contact should ever ask for your seed phrase or private key.

check the destination

Before signing, review the destination, asset, amount, network and requested permissions. Treat unlimited approvals and unfamiliar contract calls with extra caution.

use official references

Verify contract addresses, applications, network endpoints and ecosystem records through the official documentation, 420 Registry and 420 Explorer when those services are live.

separate risk

For higher-value use, consider separate accounts for long-term storage, everyday application interaction and experimental testnet activity.

Security documentation will expand with phishing guidance, contract verification, wallet recovery and incident-response procedures before public genesis.
