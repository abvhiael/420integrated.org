Developers / Contracts

contract interfaces.

Application integrations should depend on published interfaces, events, errors and canonical registry records instead of hard-coded assumptions.

addresses & discovery

Canonical production and testnet addresses will be published alongside registry references and deployment versions. Consumers should resolve official records before interacting with contracts.

ABIs, events & errors

Each supported integration surface will document callable functions, emitted events, custom errors, permission requirements and expected state transitions.

version compatibility

Clients should pin known-compatible interfaces and handle upgrades explicitly. Breaking changes should be reflected through versioned interfaces, registry metadata or migration guidance rather than silent behavior changes.

Exact addresses, ABIs and version matrices remain unpublished until their corresponding deployments are qualified.
